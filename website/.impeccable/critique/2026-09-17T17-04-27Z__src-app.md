## Priority issues

### [P0] Primary CTA fails contrast because an unlayered rule kills every text-colour utility on anchors

globals.css:173 declares an unlayered `a { color: inherit }`. Tailwind v4 emits utilities inside @layer utilities, and unlayered beats layered regardless of specificity. Verified by byte offset in the production bundle: utility at 15806 inside @layer utilities, project rule at 25964 unlayered. Measured: "Baixar .exe" declares text-[var(--accent-ink)] (#1b0f0d) and renders rgb(236,231,225) — 2.15:1 against a required 4.5:1, where the intent was 7.08:1. 90 anchors across three pages render a colour other than the one they declare; the 40 docs sidebar links resolve ivory instead of --muted, erasing the rail hierarchy.

Fix: wrap the project reset in @layer base (preferred), or scope it to a:not([class*="text-"]). Re-verify the 90 anchors.
Command: $impeccable harden

### [P1] The benchmark chart fabricates a time series and contradicts its own methodology page

benchmark-chart.tsx plots five monthly points with local values .62/.65/.59/.61/.60. content/docs/referencia/benchmarks.md states there is one measurement: 0.6s on an RTX 4050. Four points and the entire axis are invented, under the heading "Desempenho que você consegue auditar." On mobile the panel collapses to 309x119px with colliding date labels and pushes the "Natureza do dado" column — the one that says which numbers are real — off-screen. Breaches PRODUCT.md: "Product claims must remain traceable to the repository, published release or labeled demonstration data."

Fix: drop the time axis. Two marks: one measured (0,6 s, annotated RTX 4050 / Large v3 Turbo q5 / README) and one explicitly hatched illustrative band (2,5-3,8 s, "cenário, não fornecedor"). The Cost view is legitimately cumulative and can keep an axis labelled "mês 1...5".
Command: $impeccable clarify

### [P1] Every list in the documentation renders without bullets or numbers

globals.css:1910: `.docs-prose ul, ol { display: grid }` blockifies the li children, removing marker rendering, and Tailwind preflight already cleared list-style. padding-left: 1.5rem still reserves the gutter, so lists read as orphaned indented lines. The next line, `.docs-prose li::marker { color: var(--accent) }`, is dead CSS proving markers were intended. Also hits the ol and ul on /download.

Fix: replace display:grid with display:flex; flex-direction:column (preserves list-item on children) and restore list-style: disc/decimal explicitly.
Command: $impeccable polish

### [P1] /download is a second design system, and hides the hash it tells you to verify

Beyond the 1280 vs 1180 misalignment: rounded-3xl = 24px off-scale; hand-rolled primary CTA instead of .button.button-primary; h1 at 60px/600 vs docs 73.6px/550. The card says "Confira o SHA-256 publicado" but the hash is never displayed — only "SHA-256: verificado" with a copy button — and checksumSource (the SHA256SUMS.txt URL) exists in the data and is rendered nowhere. CPU vs CUDA requires memorising the card that disappeared; the 43x size difference is never co-visible. The SmartScreen card warns about the dialog without saying what to click.

Fix: port to .shell and the semantic layer. Render the hash in mono with a visible SHA256SUMS.txt link. Show both variants side by side (size, requirement, "choose this if..."), raising the selected one rather than erasing the other, with a check glyph so state is not colour-only. Expand SmartScreen into the literal steps.
Command: $impeccable shape

### [P2] The docs search dropdown is clipped, un-dismissable and keyboard-hostile

"cuda" returns 6 results into a max-h-96 panel: the 4th result is cut mid-card with the sidebar nav bleeding through beneath. No Escape handler, no outside-click, no clear button. The container is role="status" aria-live="polite" and contains links, so every keystroke re-announces the whole list; with no combobox pattern the arrow keys do nothing. Two results carry contradictory section labels because faq.md declares a different section value from its siblings, which also splits the sidebar into a 1-item group followed by a near-homonym.

Fix: max-h-[min(70vh,32rem)] with an opaque edge; Escape + outside-click + clear; move aria-live to a visually-hidden node announcing only the count; implement the combobox pattern with arrow keys; add Ctrl+K and /. Fix the faq.md frontmatter.
Command: $impeccable harden

## Persona red flags

Privacy-conscious corporate evaluator: the answer that decides their evaluation (optional cloud summaries send text, not audio) is collapsed in a FAQ at ~76% page depth. Clicking "Experimentar ditado" lights a terracotta microphone orb on a marketing site, and the only mitigation ("nenhum áudio é capturado") is 11.5px, the smallest type on the page, at the top of the frame away from the orb — the reassurance is smaller and further away than the alarm. They reach /download, read that the binary is unsigned, and the hash they are told to check is not there.

First-timer: the fourth hero element, before any feature, is a cargo build command; on mobile it sits above the demo. They learn the wrong shortcut (the demo shows Ctrl+Shift+Espaço, the default is Ctrl+Alt+Espaço — a deliberate plan decision labelled "Atalho configurável", but the label does not survive memory). On mobile the header drops the CTA entirely: .header-download and .github-link are display:none, and the menu lists "Download" at the same weight as "Recursos".

Technical evaluator: opens #benchmarks first and finds the fabricated series — the persona most likely to notice and with the most word-of-mouth weight. Tabs into the demo and hits two dead controls: the titlebar "Biblioteca" and "Configurações" buttons have no handler. Both assessments independently found aria-controls="stage-panel-meeting" pointing at an id that does not exist in the DOM.
