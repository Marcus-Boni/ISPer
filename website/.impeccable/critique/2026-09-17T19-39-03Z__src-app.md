## Priority issues

### [P1] /download asks for verification it makes impossible
The panel shows the SHA-256, a copy button, a link to SHA256SUMS.txt and the instruction to compare it against the downloaded file — and nowhere on the portal is there a command that computes that hash. This is the Operate surface for an unsigned binary aimed at teams who cannot send audio to a SaaS; the evaluator most likely to verify is handed 64 characters and no tool. The SHA256SUMS link also has no target="_blank", so it navigates away from the hash being compared.
Fix: a second monospace row with `Get-FileHash .\<file> -Algorithm SHA256`, filename interpolated from the selected variant, plus a copy button; open the checksum source in a new tab and announce it as the header already does.

### [P1] The docs read at 95 characters per line and lose their contents below 1280px
.docs-prose caps at 47.5rem, measured 696px of text at 16px/1.8 = 95 characters per line against DESIGN.md's committed 65–75ch — the widest prose cap on the site, on the only surface anyone reads for more than thirty seconds. Separately the contents rail is hidden entirely below 1280px with no fallback, while the navigation gets a collapsed disclosure.
Fix: a ch-based cap around 62ch, matching the other surfaces; a collapsed "Nesta página" disclosure below 1280px reusing the mobile-nav pattern. OnThisPage already computes the active heading at every width; it has nowhere to render.

### [P1] Mobile menu plus viewport resize is a trap
Reproduced: open the menu at 390px, resize to 1512px. Both navs render, body keeps overflow:hidden, and .menu-button is display:none — the page is scroll-locked with no visible close control. .mobile-nav { display: grid } carries no media query and open state never resets on resize. A tablet rotating portrait to landscape crosses this breakpoint.
Fix: scope the rule to the breakpoint and close the menu on a matchMedia change.

### [P2] Terminology splits on the product's most sensitive noun
"provedor" appears 15 times and "provider" 9 times in user-facing copy, including both spellings in one sentence in the semantic-search privacy doc, and "Provider opcional" in the landing comparison table while the boundary diagram 3000px above says "Provedor de IA que você configurar". The provider is the only thing that can carry text off the machine.
Fix: standardise on provedor in prose and UI; reserve "provider" for a literal control in the desktop app and say so.

### [P2] Five of seven landing h2s are the same size, so the close cannot out-rank anything
Measured 65.6px/700 for the boundary, recursos, biblioteca, benchmarks and final CTA; 40px for shortcut and FAQ. Four of the large ones run consecutively. The section step was introduced so nothing could be second-loudest, then applied only to the two supporting sections — and a sixth large heading was added with the boundary section.
Fix: move recursos and stage-section to the section step, or give the boundary a distinct treatment; it is the only section that deserves to be loudest.

## Persona red flags

Power user: the demo's meeting clock loops 00:00 → 00:08 → 00:16 → 00:24 → 00:00 under a "gravando reunião" chip, so the one interactive thing on the page is the one thing that is not true; "Busca local na Biblioteca" sits among two working buttons as a dead span; the hero's cargo command overflows its field by 5px at 1512px and truncates mid-token at 1024px, because the pre-wrap fix only applies below 640px.

First-timer: on a phone the persistent Baixar CTA disappears entirely and the only route is a text link inside the hamburger; the CONTRATO badge is defined nowhere; .hero-proof orphans "Sem bot na chamada" onto its own row.

Privacy evaluator: the verification instruction with no verification command; the audio claim in a stock blue Note box on the page a security reviewer actually reads; provider/provedor in the same privacy sentence; hardcoded SmartScreen copy that cannot tell the truth if signing status changes; the comparison table paints its own column green, header included, while the "no vendor was evaluated" disclosure is the smallest type on the section.

And, confirmed by both assessments: the cross-route anchor never fires for reduced-motion or touch users. smooth-scroll.tsx returns early for prefers-reduced-motion and pointer:coarse, and the anchor effect then bails on `if (!lenis) return` — so on every touch device, tapping Recursos from a docs page lands at the top of / with #recursos in the address bar, exactly the failure the code comment says the effect exists to prevent. Measured with Lenis on, the section also lands 188px below the viewport top against 92px for a direct load, because the JS offset stacks on the element's own scroll-margin-top.
